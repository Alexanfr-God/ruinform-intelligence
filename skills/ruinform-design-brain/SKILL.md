# RUINFORM Design Brain Skill

Use this skill when the task is to invent what real source objects could become inside the RUINFORM world.

## Inputs

- original source photographs
- ProjectState / material IDs
- optional user intent
- optional relevant Taste Library references
- optional relevant Eval Library successes / failures
- RUINFORM style rules

## Required behavior

1. Look at the original photographs directly before proposing concepts.
2. Treat photographed matter as primary evidence; text labels are secondary.
3. Preserve recognizable provenance: color, wear, seams, zippers, dents, scratches, material character, proportions.
4. Invent transformations, not decorations.
5. Reject the first obvious combination.
6. Avoid generic cyberpunk, random RGB, pouch/sleeve solutions, stacked-object sculpture, and craft-collage aesthetics.
7. Prefer one strong silhouette, one material tension, one signature gesture, and one clear reason to exist.
8. Keep added parts subordinate to the reclaimed source matter.
9. Keep high-consequence physical unknowns explicit instead of inventing facts.
10. Return structured data that downstream image and build modules can reuse without losing the original photos.

## Wave 1 learned quality gates

### Signature Gesture
Every strong concept should have one visual event the viewer can remember and describe later. If the memorable part is merely "a lot of cool components," simplify.

### Concept Compression
The central magic should be explainable in one short sentence. A concept that requires a long engineering explanation before it becomes interesting is probably overbuilt.

### Transformation Delta
Prefer maximum change in perception from minimum justified intervention. New relationships, behavior, negative space, tension, frozen action, or role reassignment matter more than decorative additions.

### Physical Story
A surprising concept still needs a believable fabrication story. If the essential transformation cannot be explained in 2–3 plausible physical steps, redesign it or surface the uncertainty. Do not rely on the image renderer to fake impossible assembly.

### WILD is not more parts
WILD means a radical gesture, form, behavior, tension, or illusion. It does not mean a longer shopping list. Every added component must enable the central gesture, necessary structure, or safety.

### Neutral-background test
Before trusting cinematic atmosphere, ask whether the object still feels authored, desirable, and collectible on a clean neutral background. The world may present a strong object; it must not rescue a weak one.

## RUINFORM world

RUINFORM is a post-consumer salvage economy: existing matter is treated as valuable stock for new desirable objects. The visual target is not cosplay apocalypse. It is contemporary collectible design made from surviving real matter.

Keywords that fit when earned by the source materials:
- salvage luxury
- repaired future
- material honesty
- industrial domestic
- post-consumer artifact
- functional scars
- visible adaptation
- asymmetric precision
- contemporary collectible design

## Quality gate

Reject concepts that can be summarized as:
- wrap X around Y
- put X inside Y without a deeper transformation
- use X as a pouch/base
- glue the source objects together
- add LEDs to make it futuristic
- hide a weak object behind a cinematic background
- add many mechanisms when one stronger relationship would do

Prefer concepts that create a new silhouette, new function, new behavior, new physical tension, or new material relationship.

## Handoff contract

The Design Brain must pass forward:
- source material IDs
- concept name and one-line identity
- function / object type
- material roles
- transformation logic
- artistic thesis
- key operations
- required additions
- unresolved dependencies

Downstream visual modules must also receive the original source images, not only this structured output.

## Success statement

A successful RUINFORM concept makes the user think:

"I can still recognize my junk, but I would never have imagined it could become this."
