# RUINFORM HACKATHON DEMO PLAN — v0.1

## Demo promise

**Photograph discarded real objects → RUINFORM invents a desirable new artifact → show the transformation beautifully.**

The hackathon demo is not the full company. It is one undeniable proof.

## Demo flow

1. Hero landing page establishes the RUINFORM world in 5–10 seconds.
2. User uploads 2–4 photos of real unwanted objects.
3. Design Brain analyzes the actual images and proposes four distinct futures.
4. User selects one direction.
5. GPT Image generates the transformation.
6. Result page shows source → future with strong presentation.
7. `MAKE IT REAL` is visible as the roadmap / next layer; detailed manufacturing can remain gated during hackathon testing.

## Closed alpha

Use invite-only / limited test sessions initially.

Reasons:
- control API spend
- collect high-quality source/result pairs
- manually review failures
- build Taste Library from real evidence
- prevent a traffic spike from turning experimentation into uncontrolled image cost

Possible controls later:
- access code
- per-user render quota
- daily global render cap
- admin-only high-quality mode
- lower-cost preview tier before final high-quality render

## What the video must prove

Record one clean end-to-end run showing:

- real source objects on camera / original photos
- upload
- RUINFORM concepts
- chosen concept
- generation waiting experience
- final transformed image
- comparison against source matter

Do not rely only on a pre-rendered montage. The viewer should see that the workflow actually runs.

## Landing-page wow

The landing page should communicate a world, not a SaaS dashboard.

Hero idea:

`THE WORLD HAS ENOUGH OBJECTS.`
`WE NEED BETTER FUTURES FOR THEM.`

Visual language:
- editorial full-screen artifact photography
- reclaimed textures used sparingly
- black / worn neutral environment
- typography with strong modern contrast
- interactive before/after matter transformation
- subtle scan / material-analysis motion
- no generic AI gradients

## Success metric

For at least 5–10 different real source sets, an evaluator should be able to say:

**"That does not look like generic AI upcycling. I would actually want that object."**
