# RFM-INT-0002.6.1 — Durable Store Startup Guard

## Problem

A production deploy must not depend on opening the database during module import or store construction. Database connectivity should be exercised when the store is actually used, while the service can still boot and expose health information.

## Change

- Make Postgres table initialization lazy and idempotent.
- Keep durable Postgres selected whenever `DATABASE_URL` / `RUINFORM_DATABASE_URL` is configured.
- Expose the selected storage backend in `/health` without exposing credentials.
- Bump the health build marker to `RFM-INT-0002.6.1`.

## Expected regression protection

A deploy/restart can boot even if the database is temporarily unavailable. The first durable store operation will still fail loudly rather than silently falling back to ephemeral SQLite.
